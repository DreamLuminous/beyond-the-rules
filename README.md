# 规则之外（Beyond the Rules）

双人协作开发的 Web AI 共创冒险：玩家与 AI 伙伴“墨点”轮流担任设计者、玩家与协作者。
比赛版范围为 2 个基础关卡 + 1 个高级关卡，三关共用同一套世界内核与数据协议。

## 现在可以验证什么

**第一关 · 悬空之桥（AI 行动）**
输入“墨点，先走到箱子旁边，观察周围的机关”，本地计划器返回 `AgentPolicy`，墨点先观察再自主移动。
第一关现在有完整的三任务：走到第一块石板 → 用石板铺路走到对岸 → 检修桥板缩回后重新规划并补上缺口。
输入“走到第一块石板上”“用石板搭一条路，然后过桥”“继续走向装置”，墨点会真实执行；
桥板缩回时它会停在缺口前报告 `PATH_BLOCKED`，你可以说“用石板补上缺口”或点“让墨点重新规划”。
通关后显示共创总结（用时、引擎执行规则数、交流次数）。也支持暂停、撤销和 `ExecutionResult` 回执。

**第二关 · 回声工坊（AI 设计，人类挑战）**
在章节切换里进入“第二关”，描述你想玩的挑战（例如“需要反射光线、有点难、最好有隐藏区域”），
墨点会生成 `LevelDraft`，验证器在网格上实际搜索镜面朝向、闸门状态与可达路径，通过后才允许试玩。
试玩使用 WASD / 方向键移动、空格跳跃、靠近镜子按 E 转动；通关后用一句话反馈（太难 / 太简单 / 想要隐藏区域 / 这里跳不过去），
墨点会生成新版本并保留上一版对比。

**第三关 · 断流之城（人机共同写规则）**
在章节切换里进入“第三关”，描述城市策略（例如“缺水时先保居民，再限制工业，也要给下游留生态流量”），
墨点会生成受限 `RuleScript`；你可以切换自然语言 / 可视化逻辑 / 规则代码三种查看方式，再运行七日模拟。
模拟器逐日计算水库、居民、能源、生态与设施状态，第 3–4 天干旱、第 5–6 天泵站故障；
巡查泵站还能找到备用泵维护记录，之后可以让墨点把备用泵写进规则。反馈修改会生成新版本并保留上一版结果对比。

演示直达：`/?level=workshop&seed=42`（载入一份已通过验证的工坊草案）、
`/?level=city&run=1`（生成规则并自动运行七日模拟）。

## 当前进度

- 第一关 V3.1 闭环：Phaser 场景与 HUD、墨点的观察/导航/推动/激活/停止/暂停、1800×720 世界、
  规则笔（重力/位移/风场）、双执行入口（`AgentPolicy` / `ActionPlan`）、世界版本、规则能量、撤销与契约测试。
  三任务（第一次指导 / 开放式过桥 / 桥板缩回后的重新规划）与共创总结已接入引擎判定。
- 第二关闭环：需求解析、`LevelDraft` 生成、`LevelValidation` 验证器（含镜子可达顺序与机关必要性）、
  可玩工坊场景、反馈重设计、隐藏区域与版本对比。
- 第三关系统层：自然语言生成受限 `RuleScript`、第一条匹配规则的解释器、七日确定性模拟、
  干旱与泵站故障、备用泵探索、三层规则查看、反馈修订与版本对比。
- 尚未实现：语音输入、城市可行走探索地图、序境实验室、完整成就系统。

## 项目结构

```text
apps/web              Phaser 游戏、React 界面、本地 Mock 设计器
apps/api              AI、语音和解释服务（占位，尚未接入真实模型）
packages/contracts    双方唯一共享协议源（Zod）
packages/rule-engine  计划预检与错误码
packages/level-data   关卡数据与能力声明
content               关卡、剧情与成就内容
tests                 契约、引擎、AI 设计与端到端测试
docs                  设计共识、分工、接口与联调说明
```

## 分支策略

- `main`：随时可演示；
- `dev`：日常集成；
- `feat/a-*`：A 的短功能分支；
- `feat/b-*`：B 的短功能分支；
- 协议变更必须两人共同评审，先更新 Schema、示例和契约测试。

## 快速开始

```bash
corepack enable
pnpm install
pnpm dev        # web + api
pnpm test
pnpm typecheck
pnpm build
```

Node.js 建议使用 20 LTS。密钥仅写入本地 `.env`，不得提交。

## 合并门槛

1. `pnpm typecheck`、`pnpm test`、`pnpm build` 全部通过；
2. 所有 AI 输出经 Zod 校验，非法草案零修改拒绝；
3. 第二关草案必须通过验证器才能载入；
4. 关卡至少保留两条已测试解法（第一关）或一条经验证的通关路径（第二关）；
5. API 故障不会冻结游戏。

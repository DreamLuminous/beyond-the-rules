# 开发者 B 计划：AI、语音与解释

> 当前状态（从 `feat/b-planner-basic` 合入）：M1 语音组件、M2 规则式规划、M2.5 关卡设计、
> M3 城市政策解析、M4 解释、M5 LLM 适配均已实现；36 条回归测试通过。
> 语音已在第一关接入，第二、三关的入口待复用同一组件。

## 交付边界

B 交付一个可独立测试的 AI 服务：读取固定 `WorldSnapshot` 和玩家原话，输出合法 `ActionPlan`；对不可执行意图明确拒绝或提出一个关键澄清问题。

## 任务清单

### M0：工程与协议（共同，半天）

- 将共享 Zod Schema 作为结构化输出唯一依据。
- 建立 30 条回归输入，覆盖同义表达、多步骤、指代、越权、超预算和语音错误。
- 制定错误码和中文用户反馈规范。

验收：测试可在无游戏环境下使用固定快照运行。

### M1：语音与输入（半天）

- Chrome 优先的按住说话/点击录音交互。
- 展示识别文本，允许提交前快速修正。
- 文字输入始终可用；麦克风拒绝、无声和浏览器不支持均有降级提示。
- 请求可取消；相同请求 ID 不重复提交。

验收：语音失败不阻塞游戏，玩家能立即切换文本输入。

### M2：基础关规划器（1～1.5 天）

- 快照压缩：只发送相关对象、能力、目标、预算和不可变对象。
- 物体指代：优先选中对象，其次空间关系和唯一标签；仍模糊时追问。
- 生成 1～16 步 DAG 计划；不生成 JavaScript 或未声明动作。
- JSON Schema 约束后再次用 Zod 校验；失败最多修复一次。

验收：“三块石板依次升起”输出有顺序的计划；“直接让我通关”被拒绝。

### M2.5：工坊关卡设计器（已完成首版）

- 解析中文需求：难度、隐藏区域、提示、主题；对敌人、联机、天气等未实现能力明确说明缺什么。
- 生成受约束 `LevelDraft`：房间组合、断口宽度、镜子与接收器位置、闸门绑定、隐藏书架。
- 生成后必须调用 A 的验证器；连续失败则保留最后一份并解释失败原因，绝不声称“已可玩”。
- 反馈修改：太难 / 太简单 / 想要隐藏 / 跳不过去 / 提示不清，映射为难度、隐藏区域、提示与布局参数，
  并保留上一版供玩家对比。
- 12 个 seed × 3 难度回归全部通过验证器；同一 seed 与需求必须得到相同草案。

验收：同一句需求不同措辞可生成合法草案；验证器拒绝时 UI 显示真实问题；反馈能改变下一版。

### M3：高级关规则生成（已完成首版）

- 将自然语言需求映射为受限 `RuleScript`：居民优先、生态下限、限制工业、备用泵、规则精简。
- 生成后必须由 A 的城市模拟器执行；AI 只解释逐日结果，不得虚构数字或改写天气。
- 反馈修订：居民不够、规则太多、启用备用泵等会生成新版本；备用泵必须先在城中巡查解锁。
- 对“新建水库 / 人工降雨 / 价格系统”等超出能力的请求明确说明缺少什么。

验收：生成的规则可执行并通过七日检查；固定配水策略被真实判定失败；同一 seed 生成相同规则。

### M4：墨点与结果解释（半天）

- 用简短语句解释计划、失败原因、代价与下一步提示。
- 区分事实（执行器结果）和建议（AI 推断）。
- 同一错误不循环重复；提示不直接泄露全部谜底。

### M5：联调与稳定（共同，1 天）

- API 超时、限流、模型拒绝、非法 JSON、过期快照、断网降级。
- 记录原话、规范计划、世界版本、结果和耗时，不记录 API 密钥。
- 关闭 AI 时，预置演示输入仍可完整展示核心链路。

- 让模型自行决定通关。
